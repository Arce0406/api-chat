# ai-call：把工作派給付費 API

## 先確認

- 執行 `ai-call --help` 看目前的選項、模型、價格與限制。**以 `--help` 為準**，這份檔案只講什麼時候用、怎麼用。
- 找不到指令就用完整路徑 `~/.local/bin/ai-call`。還是沒有，代表這台沒裝，改在主對話做。

## 什麼時候派出去

判斷方式：**這件事能不能把需要的資料附上、寫清楚要什麼，一次問完？** 能就可以派。

最划算的是輸入大、輸出小的工作，例如讀很多檔案或長 log 只要結論。主對話只交出路徑、只讀回結果，省下最多訂閱額度。**原始資料不要先讀進主對話**，直接交給 `-f`。

其他工作也可以派，例如寫草稿、翻譯、審閱、產生程式碼。省的比較少，因為主對話還是要讀結果，但生成的部分改用 API 額度。

## 目前工具做不到的（不是不該派，是還沒支援）

後續功能會陸續加入。

| 限制 | 影響 | 現在的做法 |
|---|---|---|
| 一問一答，沒有多輪對話 | 要來回修改的工作，每次都要重新附上全部內容 | 需要反覆修改時，把上一版和修改意見一起附上再問一次 |
| 不能讀檔、跑指令、上網 | 模型只看得到 `-f` 附上的內容 | 改程式碼：讓它產生程式碼或修改建議，由主對話套用並跑測試 |
| 只收文字、只回文字 | 不能讀圖片和 PDF，不能產生圖片、語音、影片 | 改在主對話處理 |
| 使用者不能直接跟它對話 | 要和使用者討論、需要使用者決定的事，要經過主對話 | 主對話跟使用者談，需要時再派出去 |

## 怎麼呼叫

```bash
ai-call --json -f path/to/a.log -f path/to/b.log "列出錯誤原因，每項一行"
git diff origin/main...HEAD | ai-call --json -f - "用三句話摘要這次改動"
```

- 一律加 `--json`，讀 `ok`、`text`、`truncated`、`costUsd`。失敗時讀 `error.kind`。
- 加 `--tag <主題>`，方便事後統計，例如 `--tag log-summary`。
- 長輸入或 Opus／Fable：Bash 的 `timeout` 設 600000，或改用背景執行。
- 模型看不到主對話的上下文。需要的背景、限制、輸出格式都要寫進指示或附檔，也可以用 `-s` 給角色和規則。

## 選模型與思考深度

| 工作 | 模型 | `--effort` |
|---|---|---|
| 摘要、分類、抽取、格式轉換、一般翻譯 | `haiku`（預設） | 不支援，不要加 |
| 需要判斷的審閱、第二意見、寫草稿、較難的翻譯、產生程式碼 | `sonnet` | `low` 或 `medium` |
| 需要深度推理的分析或第二意見 | `opus` | `medium` |
| — | `fable` | 只在使用者指定時才用（最貴） |

不確定時選較便宜的那一級，結果不夠好再升級。

## 結果處理

- `truncated: true`：回覆被截斷。加大 `--max-tokens`，或把工作拆小。
- `error.kind` 為 `credentials`：金鑰沒設好。告訴使用者，不要自己找其他金鑰代替。
- `error.kind` 為 `refusal`：模型拒答。改在主對話處理，或請使用者決定。
- `rate_limit`、`overloaded`：等一下重試一次。還是失敗就改在主對話做。
- 回報給使用者時附上這次花費（`costUsd`），例如「派給 Haiku 摘要，花了 US$0.002」。
- 派出去的結果是另一個模型的意見。重要結論要自己抽查，不要當成已驗證的事實轉述。
